## Compatibility, bounds and cancellation

The generic client driver now requires `C::BidiStream: Send`. This is an accepted compatibility requirement of its independent boxed dispatch futures and applies even to a client not enabling the extension. Quinn satisfies it. Detached Server sessions require a splittable `quic::BidiStream` and a cloneable opener. Each backend opener clone must own independent pending-open state, as Quinn does; sharing one pending future behind a mutex would overwrite waiter wakers. The crate spawns no tasks.

Client defaults are 1 session, 32 raw queued streams, 32 incomplete prefixes and 32 validated queued streams per session. Server defaults are 1 active/reserved session, 32 raw accepts per poll, 32 incomplete classifiers and 32 queued validated bidi streams per session. Nonzero limits are configurable. Prefix, intake and delivery work yields in batches of at most 32. Prefixes decode at most two QUIC varints using an eight-byte scratch buffer. Server classification inspects at most two frame-header varints and incrementally skips unknown leading H3 frame payloads. It never buffers a peer-declared WT prefix length. Ordinary request headers are resolved by bounded/deadlined application tasks, outside the classifier. Saturation resets newest arrivals, including ordinary requests when all Server classifier slots are occupied.

Both peers' selected SETTINGS caps and the configured local cap constrain establishment. Server admission reserves under a mutex before awaiting response writes. Cancellation/drop releases weak registrations and queued streams; Server close/observed peer termination frees active-session capacity even with a terminated handle retained. The earlier client API retains its reservation while its session handle remains alive, so drop a closed client handle before replacement when at its cap. Neither side hardcodes an application one-session policy. Unknown/stale IDs are rejected, never buffered for a future session. Pending known CONNECTs may buffer streams within their queue bound.

Wrong/stale session IDs and invalid/truncated WT prefixes reset and stop bidi streams with `WT_SESSION_GONE`, `0x170d7b68`. Saturation uses `0x3994bd84`. Admission cancellation and CONNECT write/FIN cancellation use `H3_REQUEST_CANCELLED`. Session termination wakes open/stream waiters and causes delivered stream guards to reset/stop on their next poll or drop. A live delivered stream retains the backend's ordinary drop semantics, so consumers must explicitly reset/stop abandoned streams. Quinn dropping a live SendStream sends FIN; the opening futures therefore have explicit abort guards for partial prefixes. Received STOP_SENDING may be noticed only on the next write, the inherited limitation discussed in upstream #350. No application behavior should depend on exact cancellation codes.

CLOSE marks streams terminal immediately, writes capsule plus immediate FIN without CONNECT grease, and waits for peer FIN in `closed()`. Peer FIN may never arrive; callers own deadlines. Data after CLOSE, including after a local-first close, is H3_MESSAGE_ERROR; a previously sent FIN cannot be retracted, so local-first trailing-data tests verify the local malformed-capsule result. Capsule processing reads at most 32 chunks of at most 1024 bytes per poll plus one retained transport chunk. Unknown capsule payloads are skipped rather than accumulated. Incoming capsule bytes wake only CONNECT readers. QUIC windows still need finite configuration. Driver loss/drop terminates registrations and drains pending/queued streams.

GOAWAY keeps ordinary H3 request semantics and permits established session data to drain. It does not implement placement sealing or withdrawal policy. The compatibility `WebTransportSession::accept` owns the entire connection, including on rejection; its eventual drop closes H3. Use `server::new` and `Acceptor::accept` to retain ordinary requests after malformed, over-cap or incompatible CONNECTs. There is no promise that cancelling core h3's initial request-header send has stronger cleanup than that pre-existing API.

## Prototype profile and deviations

For Runewarp, pin Draft07 on both peers: SETTINGS max-sessions codepoint `0xc671706a`, Extended CONNECT token `webtransport`, WT bidi signal `0x41`, full CONNECT session ID and raw bidi data. Ordinary GET zero then CONNECT four remains session four, never one. The original `into_parts` experiment becomes `server::new` plus independent `Acceptor`, `Session` and `SessionOpener` ownership. This preserves ordinary GET/PUT and Server-opened streams without a per-stream client acceptance RTT.

The adopted groups also advertise/negotiate Draft02 for drafts 02–06, Draft07 for 07–11, Draft13 for 13–14 and Draft15 for 15–16. This is negotiation and the tested stream/close subset, not full conformance to every draft. Draft12 flow control is not implemented. Draft13's wire cap is one. Draft15's enable flag has no session count, so local `Limits` still bound it. Draft02 uses exactly one request offer `sec-webtransport-http3-draft02: 1` and response `sec-webtransport-http3-draft: draft02`; later groups ignore that legacy response header.

Unlike the prototype, generic multi-session admission, independent bounded prefix parsing and capsule processing live in the extension crate. No Tunnel gate, mTLS admission, authorization, Visitor metadata, capacity or withdrawal code is ported. The client accepts Server-opened bidi streams but does not expose client-opened WT streams. Server receipt is covered using raw valid client streams. Detached uni dispatch, application subprotocol negotiation, modern WT flow-control capsules and session datagram routing remain deferred. Both detached drivers reject completed unsupported WT uni streams; silent incomplete uni headers still use the underlying core/transport intake rather than a new bounded WT uni registry. The low-level Server opener retains uni opening for compatibility, not an end-to-end detached uni promise.

The prototype demonstrated raw H3 Datagrams using a retained QUIC handle and full session ID, with RFC 9297 quarter-ID encoding on the wire. This layer neither replaces that datagram codec nor exposes a detached session datagram router. Future same-session datagram integration and all Public QUIC association policy remain separate work. No browser interoperability test or production load/fairness benchmark is claimed.

## Security review and deliberate deferrals

Primary GitHub PR bodies, commit lists and complete diffs were reviewed on 2026-10-24 UTC. All three remain OPEN and absent from this stack. They overlap and must not be blindly cherry-picked together. Per #253, adopting a reviewed security change belongs in the adopted layer, followed by ordered rebases and full validation. This final layer does not silently rewrite earlier branches. The deferrals below are maintenance risks, not claims that the parser is secure.

Set finite `max_field_section_size` on both application builders; documentation and the Server example use the prototype's 16 KiB decoded limit. This reduces QPACK amplification and header-count exposure at that configuration. Detached drivers intentionally do not expose uni acceptance. The older uni API retains that upstream limitation.

## Validation for this final layer

Both `perl -e 'alarm 300; exec @ARGV' cargo test --workspace --all-features` and the default-feature workspace suite pass 341 tests, including 20 new Server integration tests and the 26 client tests. Every new asynchronous test has an internal five-second deadline. Focused tests cover GET-before-CONNECT IDs, bidirectional FIN/data, independent ordinary PUT, multi-session routing, stale/wrong/invalid/truncated prefixes, slow-prefix independence, 400/429 and draft/settings mismatch recovery, all draft groups, reservations under blocked response writes, cancellation release, close/drain from both peers, trailing DATA after CLOSE, peer-FIN deadlines, driver/connection loss, concurrent credit-blocked opens and cancellation/recovery, partial-prefix reset/stop, close-write/FIN cancellation, both dispatch saturation stages, unsupported uni rejection, and GOAWAY with session data plus saturation cleanup.

`cargo fmt --all -- --check`, `git diff --check`, strict Clippy for workspace all-feature libraries, strict Clippy for the Server test/example, and strict Clippy for the existing client test pass. Workspace all-target/all-feature Clippy succeeds with exactly 16 pre-existing warnings, matching the prior layer by message and primary file/line/column. `bash ci/example_test.sh` passes.
